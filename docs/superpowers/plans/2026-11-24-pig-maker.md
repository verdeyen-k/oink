# Oink Pig Maker Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A browser pig maker where the kid draws 32×32 pixel-art Idle/Walk/Attack animations for all 129 Oink pigs + the Mega Boar, with automatic mixes for undrawn mixed pigs, auto-save and `pigs.js` export.

**Architecture:** Pure logic lives in two small files that run in both the browser and Node (`elements.js`: elements, pig keys, merging; `pigart.js`: frames, default pig, automatic mix, encode/decode). `maker.js` is the UI only and calls into those. Tests use `node:test`.

**Tech Stack:** Plain HTML + JS, no build step, Fredoka from Google Fonts, Node 20 `node --test` for tests.

**Spec:** `oink/docs/superpowers/specs/2026-11-24-oink-design.md`

## Global Constraints

- Element circle order: fire, ice, plant, rock, air, electric, dark, water; each beats only the next one. `common` beats nothing and is beaten by nothing.
- 9 + 36 + 84 = 129 pig keys, plus `megaboar`. Pig key = element ids in circle order (common last) joined with `+`.
- Grid 32×32. Animations `idle`, `walk`, `attack`; 4 frames to start, 1–8 allowed.
- Element icons and colours reuse Tower Trample's: fire 🔥 #ff6b3d, ice ❄️ #a5e8ff, plant 🌿 #51cf66, rock 🪨 #b08d6a, air 🌪️ #dfe8f0, electric ⚡ #ffd43b, dark 🌑 #9775fa, water 💧 #4dabf7; common ⚪ #f4a6b8 (pig pink).
- Export file: `window.OINK_PIGS = {...};` containing only hand-drawn pigs.
- No GitHub repo or push without a grown-up's OK. Local `git init` and commits are fine.

## Review Focus

1. Loading a broken or wrong file: show a friendly message and keep the current pigs untouched.
2. localStorage full or blocked: drawing still works and a warning shows that saving failed.
3. First stroke on an "auto" pig: the auto frames are copied in first, so the drawing doesn't wipe the mix.
4. Deleting the last frame is refused (min 1) and adding a 9th is refused (max 8).
5. Changing a one-element pig makes every undrawn mix using it update (no stale cache).

### Task 2: Pig pictures (`pigart.js`)

**Files:** Create `oink/pigart.js`, `oink/tests/pigart.test.js`.

**Interfaces — Consumes:** Task 1. **Produces** (`window.OinkArt` / `module.exports`):
- `SIZE = 32`, `ANIMS = ['idle','walk','attack']`, `MIN_FRAMES = 1`, `MAX_FRAMES = 8`
- A frame is an `Array(1024)` of `'#rrggbb'` or `''` (see-through), index `y*32+x`.
- `blankFrame()`, `blankPig() -> {name:'', anims:{idle:[4 blank], walk:[...], attack:[...]}}`
- `defaultPig(color) -> pig`: a simple built-in pig drawing facing right (dark outline, body in `color`, lighter snout, eye, ear, 4 legs). Idle bobs 1px on frames 2–3, walk swaps legs, attack leans 2px forward on frames 2–3.
- `mainColor(pig) -> string|null`: most-used colour across all frames, skipping `''` and dark colours (luminance < 0.2).
- `resolvePig(key, pigs) -> {pig, auto:boolean}`: `pigs[key]` if drawn; otherwise a single element → `defaultPig(color)`; `megaboar` → `blankPig()`; a mix → `autoMix`.
- `autoMix(key, pigs) -> pig`: take `resolvePig(first element)` frames. For each frame, pixels equal to the first pig's main colour are recoloured by vertical stripe across that frame's non-see-through bounding box: stripe `k = floor((x - minX) * n / width)` gets element k's main colour (from `resolvePig` of that single element, falling back to its element colour). Everything else stays.
- `encodePig(pig) -> {name, palette: string[], anims: {idle: string[], ...}}` with one character per pixel: `.` is see-through, otherwise the palette index from `0-9a-zA-Z` (max 62 colours; extra colours map to the nearest palette colour).
- `decodePig(obj) -> pig`, which throws `Error` on a bad shape (wrong length, unknown char, missing anims).

- [ ] **Step 1: Write failing tests**: encode→decode round trip equals original; decode throws on a 1023-long frame; `mainColor` ignores `#000000` even when it's the most used; `autoMix('fire+water', {})` frames contain both fire's and water's main colours, and the left-most body pixel is fire's colour and the right-most is water's; with `pigs.water` hand-drawn in `#123456`-dominant colour the mix uses `#123456`; `resolvePig('fire+water', {'fire+water': p}).auto === false`; `resolvePig('megaboar', {})` is blank.
- [ ] **Step 2:** `npm test` → FAIL.
- [ ] **Step 3:** Implement.
- [ ] **Step 4:** `npm test` → PASS.

### Task 3: The maker page (`maker.html`, `maker.js`)

**Files:** Create `oink/maker.html`, `oink/maker.js`, `oink/index.html` (a placeholder linking to the maker), `oink/README.md`.

**Interfaces — Consumes:** Tasks 1–2. Storage key `localStorage['oink-pigs-v1']` = JSON of `{key: encodePig(pig)}` for drawn pigs only.

Layout and behaviour as in the spec's "The pig maker" section:
- Left: list with sections (1 element / 2 / 3 / 🐗 Mega Boar), a thumbnail per pig (idle frame 1), ✅ or "auto" badge, a "N / 130 drawn" counter, and element filter buttons (show pigs that contain that element).
- Middle: grid canvas (checkerboard for see-through), tools pencil / eraser / fill / eyedropper / mirror-flip (whole frame) / clear, undo/redo (per pig, 50 steps), 16-colour palette (9 element colours + black, white, greys, browns, pink) + `<input type=color>`.
- Animation tabs Idle/Walk/Attack; frame strip with add (copy of current), delete, move left/right, onion-skin toggle; preview canvas looping with a speed slider (2–12 fps, default 6).
- Name box; "Copy from…" (a select of all pigs → copies its resolved frames); "Start again from the mix" (deletes the hand-drawn pig after a confirm).
- First edit on an auto pig: store `resolvePig` frames as a drawn pig, then apply the edit.
- Header buttons: Export `pigs.js` (download), Load file (accepts `pigs.js` or `.json`, parses the object after `window.OINK_PIGS =`, decodes every pig before replacing anything, shows a message on error).
- Saving: write after each stroke ends; on exception show "⚠️ Couldn't save!" in the header.
- Keyboard: B pencil, E eraser, G fill, I eyedropper, Ctrl+Z / Ctrl+Y, ←/→ frames.
